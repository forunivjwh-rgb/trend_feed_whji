# trend_feed_whji

분야별로 무엇이 뜨는지 매일 한 화면으로 보는 개인용 피드. 설계는 [`docs/SPEC.md`](docs/SPEC.md).

## 지금 되는 것 (명세 9번 "처음 순서" 1~3단계 일부)

1. **수집과 저장**: 매일 여섯 곳에서 항목을 모아 그날의 숫자를 저장한다.
2. **"지금 인기" 피드 화면**: 오늘 많이 오른 순서로 한 페이지를 만든다. 기준선(평소 값)이 14일 쌓이기 전이라 "평소 대비" 점수와 롤업은 아직 없다.

3. **실탐 요약**: "지금 인기" 위에서 10건의 원문을 읽고 LLM(Claude API, 기본 모델 Haiku 5.5)으로 "무엇 · 왜 나왔나 · 어떻게 쓰이나 · 댓글 논점"을 요약해 카드에 붙인다. LLM 키가 없으면 이 부분만 건너뛴다.

주제 묶기, "평소 대비" 점수, 인스타그램은 아직 없다.

| 분야 | 소스 | 가져오는 것 | 저장하는 숫자 |
| --- | --- | --- | --- |
| 개발·OSS | Hacker News | 인기글 위에서 60개 (공식 공개 API) | 점수, 댓글 수 |
| 개발·OSS | GitHub trending | 일간·주간 목록 (공개 페이지 읽기) | 전체 별 수, 포크 수, 오늘·이번 주에 늘어난 별 수 |
| AI | Hugging Face | 인기 모델 위에서 40개 (공개 API) | 좋아요, 다운로드, trending 점수 |
| 한국 IT | GeekNews | RSS 피드의 최근 글 20개 | 없음 (새 글을 1건으로 센다) |
| 문화·시사·밈 | Wikipedia 한국어·영어 | 일간 조회수 위에서 각 100개 (공개 조회수 API) | 그날 하루 조회수 |
| 영상·숏폼 | YouTube 인기 차트 | 한국 차트 위에서 최대 250개 (Data API v3, **무료 키 필요**) | 조회수, 좋아요, 댓글 수 |

유튜브만 키가 필요하고 나머지는 키나 로그인이 필요 없다. **키가 없으면 유튜브만 건너뛰고 나머지는 그대로 돈다.** 그날 실행 기록과 피드 화면의 유튜브 줄에 "입력 없음 — API 키 없음"이라고 나온다.

### 순위는 이렇게 매긴다

- **하루 증가량**: 항목마다 하루에 숫자가 얼마나 늘었는가. GitHub는 "오늘 늘어난 별"을, Wikipedia는 하루 조회수를 직접 알려 준다. Hacker News와 Hugging Face는 이전 기록과의 차이로 재고, 처음 본 항목은 올라온 뒤의 하루 평균을 쓴다. 숫자가 없는 GeekNews는 새로 올라온 날에 1건으로 센다.
- **어텐션 = 보통의 몇 배**: 하루 증가량을 그날 그 소스의 가운데(중간값) 항목의 증가량으로 나눈다. 소스마다 숫자 크기가 달라서 이렇게 같은 잣대로 바꾼다.
- 전부 코드가 계산한다. 결과는 따로 저장하지 않고 저장된 숫자에서 그때그때 계산하므로, 식을 바꿔도 지난 날짜를 다시 계산할 수 있다.

## GitHub Actions 로 자동 실행 (내 컴퓨터 없이)

GitHub Actions 는 GitHub 가 빌려주는 서버에서 정해 둔 일을 자동으로 돌려 주는 기능이다. 내 컴퓨터가 꺼져 있어도 돈다.

**돌아가는 모습**

- **하루 4번**(한국 시간 04:17 · 10:17 · 16:17 · 22:17쯤) 수집하고 피드를 새로 만든다. GitHub 사정으로 몇 분에서 수십 분 늦거나 가끔 한 번을 건너뛸 수 있다. 그래서 여러 번 돌린다.
- **숫자 기록**은 `data` 브랜치에 하루에 파일 하나(`days/2026-11-16.jsonl`)로 쌓인다. 같은 날 다시 돌면 그날 파일을 고쳐 쓴다. 코드가 있는 `main` 브랜치는 건드리지 않는다.
- **피드 화면**은 GitHub Pages(웹 주소)에 올라간다. 폰 브라우저로 그 주소를 열면 되고, 홈 화면에 추가해 두면 앱처럼 열 수 있다.
- GitHub trending 을 GitHub 가 서버에서 막으면 그 소스만 "주의 — GitHub가 요청을 막아 건너뜀"으로 남기고 나머지는 그대로 돈다. 막힌 것을 돌아가려 하지 않는다.
- 유튜브 키가 없으면 유튜브만 건너뛴다.

**처음 한 번 할 일** (전부 GitHub 웹 화면에서, 폰으로도 된다)

1. **코드를 `main`에 합친다.** 예약 실행은 기본 브랜치(`main`)에 있는 것만 돈다. 합치기 요청(PR)의 `Merge pull request` 버튼을 누른다.
2. **Pages 를 켠다.** repo 의 `Settings` → 왼쪽 `Pages` → `Build and deployment` 의 `Source` 를 **`GitHub Actions`** 로 바꾼다.
   - 이 repo 는 비공개다. 무료 요금제에서는 **비공개 repo 에 Pages 를 켤 수 없다.** repo 를 공개로 바꾸거나(`Settings` → 맨 아래 `Change visibility`) GitHub Pro 로 올려야 한다.
   - Pages 주소는 **주소를 아는 누구나** 볼 수 있다(비공개 repo 여도 그렇다). 피드에는 공개된 글의 제목·링크·숫자만 있고 개인 정보나 키는 없다.
3. **키를 Secrets 에 넣는다.** 유튜브 키와 LLM 키 두 개다(아래 "유튜브 키를 Secrets 에 넣기", "LLM 키를 Secrets 에 넣기"). 없는 키는 건너뛰어도 된다. 그 키를 쓰는 부분만 빠지고 나머지는 돈다.
4. **한 번 돌려 본다.** repo 의 `Actions` 탭 → 왼쪽 `수집과 피드` → 오른쪽 `Run workflow` → 초록 `Run workflow` 버튼. 1~2분 뒤 초록 체크가 뜨면 된 것이다.
5. **피드 주소를 확인한다.** `Settings` → `Pages` 맨 위에 주소가 나온다. `https://(계정이름).github.io/trend_feed_whji/` 꼴이다.

**유튜브 키를 Secrets 에 넣기**

Secrets 는 GitHub 가 키를 암호로 잠가 보관하는 곳이다. 한번 넣으면 다시 볼 수 없고(고쳐 넣기만 된다) 실행 기록에도 `***`로 가려진다.

1. 아래 "유튜브 키 발급"의 1~5번으로 키를 만든다. 5번에서 `애플리케이션 제한사항`은 반드시 `없음`으로 둔다(GitHub 서버 주소는 매번 바뀐다).
2. repo 의 `Settings` → 왼쪽 `Secrets and variables` → `Actions`.
3. `New repository secret` 을 누른다.
4. `Name` 에 정확히 `YOUTUBE_API_KEY` 라고 적는다(대문자, 밑줄).
5. `Secret` 에 키를 붙여 넣고 `Add secret` 을 누른다.
6. 위 4번처럼 `Run workflow` 로 한 번 돌려, 실행 기록의 `youtube` 줄이 `정상 …건` 인지 본다.

키는 실행하는 동안만 그 서버의 `.env` 파일에 놓였다가 서버와 함께 지워진다. 코드·설정·기록 파일·`data` 브랜치에는 들어가지 않는다.

**LLM 키를 Secrets 에 넣기**

실탐 요약은 Claude API 를 쓴다. Claude 구독(앱 요금제)과는 **별개로** 쓴 만큼 돈이 나간다. 기본 모델인 Haiku 5.5 로 하루 10건 안팎을 요약하면 한 달에 몇백 원 수준이지만, 정확한 금액은 실제 사용량(피드 맨 위 "실탐 · 요약" 칸의 토큰 수)을 보고 판단한다.

1. 브라우저로 <https://platform.claude.com> 에 들어가 가입·로그인한다(Claude 앱 계정과 별개의 개발자용 화면이다).
2. 결제 수단을 등록하고 소액을 충전한다(`Settings` → `Billing`). 충전한 만큼만 쓰이게 해 두면 안전하다. 자동 충전은 꺼 둔다.
3. `API keys` 메뉴에서 `Create Key` 를 누른다. 이름은 아무거나(예: `trend-feed`). `sk-ant-` 로 시작하는 긴 글자가 **한 번만** 보이니 바로 복사한다.
4. 이 repo 의 `Settings` → `Secrets and variables` → `Actions` → `New repository secret`.
5. `Name` 에 정확히 `ANTHROPIC_API_KEY`, `Secret` 에 키를 붙여 넣고 `Add secret`.
6. `Actions` 탭에서 `Run workflow` 로 한 번 돌려, 실행 기록에 `실탐: 요약 …건` 이 나오는지 본다.

- 모델을 바꾸려면 `config/settings.toml` 의 `[llm]` 에서 `model` 값만 고친다(GitHub 웹에서 파일을 열어 연필 아이콘으로 고칠 수 있다). 예: `"claude-sonnet-5-5"`. 더 좋은 모델일수록 비싸다.
- 실탐을 끄려면 같은 파일 `[deepread]` 의 `enabled` 를 `false` 로 바꾸거나, Secrets 에서 `ANTHROPIC_API_KEY` 를 지운다.
- 키를 대화창·코드·설정 파일에 붙여 넣지 않는다. 새어 나간 것 같으면 3번 화면에서 그 키를 지우고 새로 만든다.

**잘 도는지 보는 곳**

| 보고 싶은 것 | 보는 곳 |
| --- | --- |
| 오늘의 피드 | Pages 주소 |
| 소스별로 몇 건 모았고 어디가 막혔나 | 피드 맨 아래 "수집 상태", 또는 `Actions` 탭 → 실행 하나 → `수집 · 피드 · 기록` |
| 쌓인 숫자 기록 | `data` 브랜치의 `days/` 폴더 |
| 빨간 X 가 떴다 | `Actions` 탭에서 그 실행을 눌러 어느 단계인지 본다. `피드를 웹 주소에 올리기`만 빨갛다면 Pages 가 아직 안 켜진 것이다(기록은 정상으로 쌓인다) |

내 컴퓨터에서 직접 돌리는 아래 방법은 그대로 쓸 수 있다. 다만 컴퓨터에서 돌린 기록과 Actions 가 쌓는 기록은 서로 합쳐지지 않는다.

## 윈도우에서 켜는 법

**1. 코드 받기.** GitHub의 이 repo 페이지에서 초록색 `Code` 버튼 → `Download ZIP`으로 받아 압축을 푼다. 예: `C:\trend_feed`. (git을 쓴다면 `git clone`도 된다.) 폴더를 나중에 옮기면 6번을 다시 해야 한다.

**2. PowerShell 열기.** 시작 메뉴에서 `PowerShell`을 찾아 연다. 아래 명령은 전부 여기에 붙여 넣는다.

**3. `uv` 설치(한 번만).** `uv`는 파이썬을 알맞은 버전으로 맞춰 실행해 주는 도구다. 설치한 뒤 PowerShell을 닫았다 다시 연다.

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

**4. 폴더로 들어가 한 번 돌려 본다.** 처음에는 파이썬을 받느라 1~2분 걸릴 수 있다.

```powershell
cd C:\trend_feed
```

```powershell
uv run python -m trendfeed daily
```

**5. 피드 화면을 본다.** 4번이 끝나면 `data\feed\index.html`이 만들어져 있다. 아래 명령은 그 페이지를 브라우저로 연다. (탐색기에서 그 파일을 더블클릭해도 된다.)

```powershell
uv run python -m trendfeed feed --open
```

글자로만 보고 싶으면 아래 둘을 쓴다. 앞의 것은 쌓인 기록, 뒤의 것은 순위다.

```powershell
uv run python -m trendfeed status
```

```powershell
uv run python -m trendfeed rank
```

**6. 매일 자동 실행 등록.** 윈도우의 "작업 스케줄러"에 `TrendFeed Daily`라는 이름으로 등록된다.

```powershell
uv run python -m trendfeed install-schedule
```

- 매일 04:00에 돈다. 시각은 `config/settings.toml`의 `[schedule]`에서 바꾸고 이 명령을 다시 돌리면 된다.
- **그 시각에 노트북이 꺼져 있거나 잠들어 있었으면, 켠 뒤에 놓친 실행을 돌린다.** 윈도우가 켜진 직후 몇 분(보통 10분 안쪽) 기다렸다가 시작한다.
- 로그인해 있는 동안에만 돌고, 인터넷이 연결돼 있어야 시작한다. 배터리로 쓰는 중에도 돈다.
- 창은 뜨지 않는다. 무슨 일이 있었는지는 `data\logs\daily.log`를 메모장으로 열어 본다.
- 해제는 아래 명령이다.

```powershell
uv run python -m trendfeed uninstall-schedule
```

노트북은 켜는 시각이 날마다 달라서 숫자를 읽는 간격이 24시간이 아닐 수 있다. 그래서 숫자를 읽은 시각을 같이 저장하고, 하루 증가량은 실제 간격으로 나눠 계산한다.

## 맥에서 켜는 법

터미널에서 `uv`를 한 번 설치한다.

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

이 폴더(repo)로 들어가서 돌려 보고, 자동 실행을 등록한다. 명령은 윈도우와 같다.

```bash
uv run python -m trendfeed daily
```

```bash
uv run python -m trendfeed install-schedule
```

맥이 그 시각에 잠들어 있으면 깨어난 뒤에 돈다. 꺼져 있었으면 그날은 건너뛴다.

## 유튜브 키 발급

유튜브 인기 차트는 구글이 주는 "API 키"(프로그램이 유튜브에 물어볼 때 내는 이용권 번호)가 있어야 읽을 수 있다. 무료이고 카드 등록이 필요 없다. 하루에 쓸 수 있는 양(10,000)이 정해져 있는데, 이 프로그램은 하루에 10 안팎만 쓴다.

구글이 화면을 가끔 바꿔서 메뉴 이름이 조금 다를 수 있다. 그럴 때는 비슷한 이름을 찾으면 된다.

1. 브라우저로 <https://console.cloud.google.com> 에 들어가 구글 계정으로 로그인한다. 처음이면 약관 동의 창이 뜬다.
2. **프로젝트 만들기.** 화면 맨 위의 프로젝트 선택 칸을 누르고 `새 프로젝트`를 고른다. 이름은 아무거나(예: `trend-feed`) 적고 `만들기`를 누른다. 만들어지면 그 프로젝트가 선택돼 있는지 맨 위에서 확인한다.
3. **유튜브 API 켜기.** 왼쪽 위 메뉴(가로줄 세 개) → `API 및 서비스` → `라이브러리`로 간다. 검색 칸에 `YouTube Data API v3`를 넣고, 나온 것을 눌러 `사용`을 누른다.
4. **키 만들기.** 왼쪽 메뉴의 `사용자 인증 정보`로 간다. 위쪽의 `+ 사용자 인증 정보 만들기` → `API 키`를 누른다. 긴 글자(키)가 나오면 `복사`한다.
5. **(권장) 키를 유튜브 전용으로 묶기.** 방금 만든 키의 이름을 눌러 들어가, `API 제한사항`에서 `키 제한`을 고르고 `YouTube Data API v3`만 체크한 뒤 `저장`한다. 키가 새어 나가도 다른 데 쓰이지 않게 하는 장치다. 그 위의 `애플리케이션 제한사항`은 `없음`으로 둔다.
6. **키를 `.env` 파일에 넣기.** PowerShell에서 이 폴더로 들어가 아래 두 명령을 차례로 돌린다. 첫째는 견본을 복사해 `.env`를 만들고, 둘째는 메모장으로 연다.

```powershell
copy .env.example .env
```

```powershell
notepad .env
```

   메모장에서 `YOUTUBE_API_KEY=` 바로 뒤에 키를 붙여 넣고(띄어쓰기 없이) 저장한다. 맥은 `cp .env.example .env` 뒤에 아무 편집기로 연다.

7. **확인.** 아래 명령을 돌려 `youtube 정상 …건`이 나오면 끝이다.

```powershell
uv run python -m trendfeed collect --source youtube
```

**키 다루기**

- 키는 `.env` 한 곳에만 둔다. 이 파일은 git에 올라가지 않는다. 설정 파일, 코드, 대화창, 메신저에 붙여 넣지 않는다.
- 프로그램은 키를 주소가 아니라 요청 머리말에 실어 보내고, 기록 파일·화면·저장 파일 어디에도 쓰지 않는다.
- 키가 새어 나간 것 같으면 4번 화면에서 그 키를 지우고 새로 만든다.

**안 될 때 나오는 말**

| 실행 기록에 나오는 말 | 뜻과 할 일 |
| --- | --- |
| API 키 없음 | `.env` 파일이 없거나 `YOUTUBE_API_KEY=` 뒤가 비어 있다. 파일 이름이 `.env.txt`가 되지 않았는지도 본다 |
| API 키가 올바르지 않음 | 키를 잘못 붙였다. 앞뒤 빈칸이나 빠진 글자가 없는지 본다 |
| YouTube Data API v3 가 켜져 있지 않음 | 3번을 하지 않았거나 다른 프로젝트에서 했다 |
| 요청 한도를 넘김 | 그날 한도를 다 썼다. 다음 날 다시 된다 |

## 어디에 무엇이 있나

| 위치 | 내용 |
| --- | --- |
| `config/settings.toml` | 숫자와 한도 전부(수집 개수, 시각, 다시 시도 횟수 등). 코드에는 박지 않는다 |
| `data/trend.db` | 저장 파일(SQLite). git에 올리지 않는다. 이 파일만 복사하면 백업이다 |
| `data/feed/index.html` | 피드 화면. 매일 실행이 끝나면 새로 쓴다 |
| `data/logs/daily.log` | 자동 실행 기록 |
| `trendfeed/rank.py` | 하루 증가량과 "지금 인기" 순위 계산 |
| `trendfeed/feed.py` | 피드 화면 만들기 |
| `trendfeed/sources/` | 수집원 하나당 파일 하나 |
| `trendfeed/db.py` | 표 구조 |
| `tests/` | 자동 시험. `uv run python -m unittest discover -s tests -t .` |

저장 파일 안의 표는 셋이다(명세 8번).

- `source_runs`: 소스별 하루 실행 기록. 건수와 상태(정상 / 주의 / 입력 없음), 이유.
- `items`: 수집한 글·저장소 하나. 제목, 링크, 출처, 처음 수집한 날.
- `item_snapshots`: 항목의 하루치 숫자. 기준선을 만드는 재료라 계속 남긴다.

## 알아 둘 것

- **상태 "주의"**는 지금은 일부만 실패했을 때(예: 글 몇 개를 못 읽음, 주간 목록만 못 받음) 붙는다. "평소보다 크게 줄 때" 기준은 실제 수집량을 본 뒤 정한다(명세 9번).
- **Hacker News 다시 확인**: 인기글 목록에서 빠진 글도 2일 동안은 숫자를 다시 적는다. 어제와 오늘의 숫자 차이를 계산하려면 같은 글의 이틀 치가 필요해서다. `follow_days = 0`으로 끌 수 있다.
- **GitHub trending**은 공식 API가 없어 페이지를 읽는다. GitHub가 화면을 바꾸면 0건이 되고 실행 기록에 "입력 없음"과 이유가 남는다. Hacker News 수집에는 영향이 없다.
- **Wikipedia 조회수는 하루 늦다.** 하루치 집계가 다음 날에 나오기 때문에 어제(UTC 기준) 값을 읽는다. 어제 치가 아직 없으면 그 전날 값을 쓰고 상태를 "주의"로 남긴다. 대문·검색 같은 문서가 아닌 페이지는 뺀다.
- **GeekNews는 하루치를 다 못 담을 수 있다.** 피드가 최근 20개만 주는데 하루에 그보다 많이 올라온다. 하루 한 번 돌리면 그 사이 글 일부를 놓친다.
- **Hugging Face의 첫날 숫자는 어림값이다.** 처음 본 모델은 "만들어진 뒤 하루 평균 좋아요"를 쓰고, 둘째 날부터 실제 하루 증가량으로 바뀐다.
- **유튜브 댓글**: 영상마다 댓글 위에서 20개(관련순)를 읽어, 서로 다른 댓글 3개 이상에 나온 말만 코드로 센다. 댓글 원문은 저장하지 않고 센 결과(짧은 말과 횟수)만 남긴다. 인기 차트는 음악·영화·게임 차트의 영상으로 채워진다.
- **실탐은 아직 임시 방식이다.**
  - 주제 묶기와 "평소 대비" 점수가 없어서, 명세의 "임계를 넘은 주제" 대신 "지금 인기" 위에서 10건을 읽는다. 같은 항목은 7일 안에 다시 읽지 않는다.
  - 읽는 도구는 명세의 Agent Reach 가 아니라 각 소스의 공개 주소에서 직접 읽는다: Hacker News(링크된 글과 댓글 20개), GitHub(README), Hugging Face(모델 카드), Wikipedia(문서 본문). GeekNews 는 글 페이지가 자동 읽기를 거절해서 읽지 않고, 유튜브는 아직 읽는 법이 없다.
  - 글 하나에서 최대 12,000자만 읽고, 어디까지 읽었는지 카드 아래 "읽은 범위"에 적는다. 읽은 원문은 요약에만 쓰고 저장하지 않는다.
  - 원문을 못 읽었으면 요약을 만들지 않는다(지어내지 않게).
  - 명세의 LLM 세 용도 중 "실탐 요약"만 있다. "주제 이름·병합"과 "왜 올랐나 한 문장"은 주제 묶기가 생긴 뒤에 붙인다.
- **피드 화면에서 아직 임시인 곳**: 주제로 묶기 전이라 카드 하나가 항목 하나다. "분야별 Top 3"은 분야 안에서 소스마다 3개씩 보여 준다. "탐색 슬롯"은 위에 나오지 않은 항목 중 무작위 5건이고, Top 5의 다섯째 자리에 탐색 1건을 올리는 규칙은 아직 정하지 않았다(명세 9번). "몰랐는데 흥미로움" 표시도 아직 없다.
- 지금까지는 본문·댓글 같은 원문을 저장하지 않는다. 그래서 2~3일 뒤 지우는 정리는 실탐(4단계)을 붙일 때 만든다.
