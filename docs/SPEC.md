# 분야별 유행 감지 시스템 — 명세 v1

2026-11-16 · 지우현

대화에서 정한 값은 확정으로 적고, 이 문서를 쓰며 덧붙인 것은 "(제안)"으로 표시했다. 아직 못 정한 것은 9번에 모았다.

## 1. 목적과 성공 기준

분야별로 무엇이 뜨는지, 왜 뜨는지를 매일 한 화면으로 보는 개인용 피드다. 판단 도구가 아니라 시야를 넓히는 도구다.

- **쓰는 이유**: 관심은 없지만 대화를 위해 알아야 하는 것(연예계 데뷔·신곡, 밈, 화제가 된 사람과 장소)을 릴스를 몇 시간씩 보지 않고 짧은 시간에 파악한다. 개발·AI 같은 관심 분야는 끌리는 것을 골라 아이디어로 키우는 출발점으로 쓴다.
- **방식**: 1단계는 조회수·별 수·점수·댓글 수 같은 숫자(메타데이터)만으로 뜨는 주제를 잡는다. 2단계(실탐)는 뜨는 주제 10개 안팎만 골라 중심 글과 영상을 깊이 읽고 요약한다.
- **성공 기준**: 매일 Top 5 중 "몰랐는데 흥미로운" 것이 몇 개인가. 목표 개수는 2주 써 본 뒤 정한다.
- **시간**: 실시간일 필요가 없다. 새벽에 시작해 오후에 확인할 때까지만 끝나 있으면 된다.

**이번 범위에서 하지 않는 것**

- 원본을 오래 모으지 않는다. 원본은 2~3일만 두고 지우고 숫자 스냅샷만 남긴다.
- 중요도를 판단하지 않는다. 많이 보는 것과 중요한 것은 다르다.
- Reddit·X·LinkedIn은 자리만 두고 연결하지 않는다.
- 차단을 피하는 장치는 만들지 않는다. 캡차나 확인 화면을 풀지 않고, IP·브라우저 지문을 바꾸거나 계정을 돌려쓰지 않는다. 막히면 그날은 멈춘다.

## 2. 하루 흐름과 실행 환경

맥미니 M4 Pro 48GB에서 매일 새벽에 자동으로 시작해 7단계를 순서대로 돌고, 오후에 확인할 때까지만 끝나면 된다. 샘플 화면은 04:00 시작을 가정했다.

1. **수집**: 고정 목록과 차트에서 항목을 모은다. 수집 칸의 약 20%는 관심 목록 밖에서 무작위로 뽑는 탐색 슬롯이다. (3·4번)
2. **숫자 스냅샷**: 항목마다 그날의 조회수·별 수·점수·댓글 수 같은 숫자를 저장한다. 오래 남기는 것은 이 숫자뿐이다.
3. **항목 속도**: 어제와 오늘의 숫자 차이로 항목별 하루 증가량을 계산한다.
4. **주제 묶기**: 비슷한 항목을 한 주제로 묶고 이름을 붙인다. (5번)
5. **점수**: 주제마다 평소 대비 정도(z), 가속, 플랫폼 폭으로 점수를 매긴다. (5번)
6. **실탐**: 임계를 넘은 주제의 중심 글·영상을 읽고 요약한다. (6번)
7. **롤업과 피드**: 일·주·월 요약과 Top 5를 만들어 피드 페이지를 쓴다. (7번)

**LLM은 세 곳에서만 쓴다.** 주제 이름 붙이기·병합(하루 1회), 실탐 요약(주제마다 1회), 주제별 "왜 올랐나" 한 문장(하루 1회에 모아서). 숫자와 순위는 전부 코드가 계산한다.

| 실행기 | 맥미니 M4 Pro 48GB | 새벽 자동 실행, 실시간 처리 없음 |
| 시간 배분(샘플 값) | 수집 38분 · 계산 6분 · 원문 읽기 57분 · LLM 9분 · 피드 생성 1분 = 111분 | 가상 값. 실제 시간은 돌려 본 뒤 기록한다 |

## 3. 분야와 수집원

5개 분야마다 수집원을 정했고, Reddit·X·LinkedIn은 같은 카드 형식으로 나중에 연결할 자리만 둔다. 수집 건수는 샘플 화면 기준의 시작값이고, 가져오는 길은 제안이다.

| 개발·OSS | GitHub trending (페이지 읽기) | 75 | 1.0 | 일간·주간 목록 합산. 공식 API 없음 |

- 소스마다 하루 한 줄로 상태를 남긴다: 정상, 주의, 입력 없음. 수집 건수가 평소보다 크게 줄면 주의로 표시하고 피드에 이유를 쓴다. 기준값은 실제 수집량을 본 뒤 정한다.
- 수집 방식은 소스마다 달라도 저장 모양은 같다. 항목 하나에 소스, 출처(올린 계정·조직·사이트), 제목, 링크, 올라온 시각, 그날의 숫자를 담는다. (8번)
- 출처는 "서로 다른 곳에서 나왔는가"를 세는 데 쓴다. 같은 주제가 출처 3곳 미만이면 순위에 올리지 않는다. (5번)

## 4. 영상·숏폼 수집

유튜브는 공식 API로, 인스타그램은 사용자가 로그인한 부계로 하루 100개를 샘플링한다. 연예·밈처럼 직접 찾기 번거로운 유행을 짧은 시간에 알기 위한 부분이다.

**유튜브**

- 인기 차트는 `videos.list`의 `chart=mostPopular`로 가져온다(지역·카테고리 지정, 1회 1쿼터). 2025-07-21부터 이 차트는 Trending 전체 목록이 아니라 음악·영화·게임 차트의 영상으로 채워진다([변경 기록](https://developers.google.com/youtube/data/revision_history)). 샘플 화면의 "5개 카테고리" 표기는 틀려서 구현 때 고친다.
- 댓글은 영상당 상위 20개를 `order=relevance`(관련순)로 읽는다. `commentThreads.list` 1회가 1쿼터라 하루 영상 250개면 250쿼터이고, 하루 기본 한도 10,000의 2.5%다([쿼터 표](https://developers.google.com/youtube/v3/determine_quota_cost)). 댓글이 막힌 영상은 건너뛴다.
- 수집 단계에서는 코드로 반복되는 유행어만 센다. 댓글을 LLM에 보내는 것은 실탐 영상뿐이다.
- 채널 RSS(`youtube.com/feeds/videos.xml?channel_id=`)는 키와 쿼터 없이 최근 영상 15개와 조회수를 준다(2026-11 확인). 기획사·화제 채널을 더할 때 쓰며, 채널은 9번에서 정한다.
- charts.youtube.com의 주간 차트는 공식 API가 없어 쓰지 않는다.

**인스타그램 릴스 (부계)**

- 방식: 사용자가 직접 로그인한 부계로 릴스를 사람이 훑어보는 속도로 하루 100개 읽는다(약 15분). 일주일 동안 경고가 없으면 200개로 올린다. 로그인과 확인 절차는 사용자가 직접 하고, 비밀번호와 인증 코드는 문서·코드·설정 파일에 적지 않는다.
- 뽑는 값: 계정, 캡션, 해시태그, 소리 이름, 좋아요·댓글 수, 위치 태그(있을 때).
- 후보 조건: 서로 다른 계정 3곳 이상에서 같은 이름(소리·해시태그·캡션 속 이름·장소)이 반복되면 후보로 올린다(시작값). 계정이 출처이므로 "출처 3곳 이상" 규칙을 그대로 통과한다.
- 다음 날 확인: 해시태그 게시물 수와 관련 가게 계정의 팔로워 수를 다시 보고 유튜브·뉴스와 교차한다. 확인용 페이지는 하루 약 20쪽까지 연다(처음 설계는 10쪽).
- 점수 가중치는 0.3으로 낮게 둔다.
- 멈춤 규칙: 로그인 재요청, 확인(챌린지) 화면, "잠시 후 다시 시도"가 나오면 그날은 멈추고 피드에 "인스타 확인 필요"를 표시한다. 우회하지 않는다.
- 위험: 자동 수집은 인스타그램 약관 위반이라 부계가 제한될 수 있고, 안전한 한도는 공개돼 있지 않다. 위험을 설명했고 사용자가 이 방식을 골랐다.
- 선택 사항(사용자 결정): 밈·핫플·연예 계정 10~20개를 부계로 팔로우하면 릴스에 걸리는 비중이 커진다. 연예 뉴스 RSS는 보조로 더할 수 있다.

**어떤 유행이 언제 잡히는가**

| 유형 | 예 | 잡히는 길 | 시점 |
| --- | --- | --- | --- |
| 소리·동작형 밈 | "L을 가져가" 챌린지 | 릴스 소리 이름 반복, 쇼츠 제목, 유튜브 댓글의 반복 문구 | 퍼지기 시작하면 빠르다 |
| 사람·장소형 화제 | 스카프 아저씨(남대문시장) | 캡션·위치 태그에서 같은 이름이 3곳 이상 반복 → 후보, 이후 유튜브·뉴스로 확인 | 며칠 늦다. 첫날은 놓칠 수 있다 |
| 연예 소식(데뷔·신곡) | 기획사 발표, 신곡 | 유튜브 음악 차트, 위키 조회수, 인스타 샘플링 | 부분적으로만 잡힌다. 기획사 채널 RSS·연예 뉴스 RSS를 더하면 나아진다(9번) |

## 5. 주제 묶기와 점수

수집한 항목을 주제로 묶고, 점수가 임계(5.0) 이상이면서 출처가 3곳 이상인 주제만 순위에 올린다. 숫자는 전부 코드가 계산하고, 아래 값은 시작값이라 2주 써 본 뒤 조정한다.

**주제 묶기**

- 항목 제목·설명을 로컬 다국어 임베딩으로 비슷한 것끼리 묶고, 같은 대상의 다른 이름을 모은 별칭 사전으로 보정한다.
- LLM은 묶인 결과에 이름을 붙이고 합칠지 판단할 때만 쓴다(하루 1회). 임베딩 모델과 유사도 기준은 9번에서 정한다.
- 출처는 항목을 올린 서로 다른 계정·조직·사이트다. 한 주제의 출처가 3곳 미만이면 순위에서 뺀다.

**점수**

```latex
\text{score} = \min(\max(z, 0),\, 8) + 1.5\,\ln(\max(a, 1)) + 0.5\,(P - 1)

z = \frac{A_t - \mathrm{med}}{1.4826\,\mathrm{MAD} + 0.8}

a = \frac{\overline{A}_{3}}{\overline{A}_{14}}
```

| 기호 | 뜻 |
| --- | --- |
| `A_t` | 오늘 주제의 어텐션(`topic_daily.attention`) |
| `med`, `MAD` | 오늘 이전 최대 4주 어텐션의 중앙값과 절대편차 중앙값. 평균보다 하루 튄 값에 덜 흔들린다 |
| `a` | 최근 3일 평균 ÷ 최근 14일 평균(오늘 포함). 지금 급하게 오르는 중인지 본다 |
| `P` | 주제가 나타난 플랫폼 수(폭) |
| 0.8 | 평소 변동이 거의 없는 주제에서 z가 폭주하지 않게 하는 완충값 |
| 8 | z의 상한 |

- 상수는 z 상한 8, 가속 가중 1.5, 플랫폼 가중 0.5, 임계 5.0, 출처 최소 3곳이다. 모두 시작값이다.
- 일별 어텐션은 그날 주제에 묶인 항목들의 속도를 플랫폼 안에서 정규화해 합친 값으로 시작한다(제안). 인스타는 합칠 때 0.3을 곱한다(제안).
- 점수 상위 4건과 탐색 1건이 Top 5이고, 분야마다 3건씩 따로 보여 준다.

**처음 2~4주**

기준선이 14일 쌓이기 전에는 z와 가속을 끄고 오늘 어텐션 순("지금 인기")으로만 보여 주고, 롤업은 숨긴다. 14일이 차면 평소 대비 점수가 켜지고, 기준선은 28일까지 점점 길어진다.

## 6. 실탐 (깊게 읽기)

임계를 넘은 주제(하루 10개 안팎)마다 대표 글·영상 1~3건을 읽고, 무엇이고 왜 나왔고 어떻게 쓰이는지를 요약한다. 숫자는 이미 코드가 계산했고, 실탐은 "그게 뭔데?"에 답하는 단계다.

- **읽을 항목**: 주제마다 대표(가장 큰 것), 발단(가장 먼저 나온 것), 최다 논의(댓글이 가장 많은 것) 중 1~3건. 샘플은 하루 20건 남짓이다.
- **읽는 도구**: Agent Reach(오픈소스). 아직 설치하지 않았고, 설치와 점검이 구현의 첫 단계다(9번).
- **재탐색 금지**: 같은 주제는 7일 안에 다시 읽지 않는다.
- **시간 예산**: 하루 90분(2번). 임계를 넘은 주제를 먼저 읽고, 남으면 탐색 슬롯을 읽는다.
- **탐색 슬롯**: 점수와 무관하게 관심 목록 밖에서 무작위로 뽑은 5건을 보여 준다. Top 5의 5번째 자리도 탐색에서 온 주제 1건이고, 점수가 임계에 못 미쳐도 "무작위 추첨으로 올라왔다"고 표시해 싣는다. 그 1건을 고르는 규칙은 9번에서 정한다.

| 읽는 대상 | 읽는 범위 (샘플 기준) |
| --- | --- |
| GitHub 저장소 | README, 이슈 |
| Hacker News 글 | 링크 원문, 댓글 상위 20 |
| 유튜브 영상 | 자막, 설명란, 댓글 상위 20 |
| Hugging Face 모델 | 모델 카드 |
| Wikipedia 문서 | 문서 본문 |
| 인스타 후보 | 다음 날 확인(4번) |

- **요약 형식**: 무엇 · 왜 나왔나 · 어떻게 쓰이나 세 항목에 댓글 논점 한 줄. 카드 아래에 읽은 범위("README 1 · 이슈 12 · HN 댓글 상위 20")를 적어, 어디까지 읽고 쓴 요약인지 보이게 한다.
- **"왜 올랐나" 한 문장**: 어느 플랫폼에서 먼저 올라 어디로 번졌는지를, 코드가 계산한 숫자 근거로만 쓴다. LLM은 새 숫자를 만들지 않는다.

## 7. 피드 화면

피드는 한 페이지이고, 위에서 아래로 Top 5, 분야별 Top 3, 탐색 슬롯, 롤업, 수집 상태 순이다. 모양은 [샘플 피드](https://claude.ai/artifact/4io9uiPSsWLwoYgfnTPMDN)가 기준이다(주제와 숫자는 모두 가상). 샘플의 소스 코드는 `docs/sample/`에 있다.

| 구역 | 보여 주는 것 |
| --- | --- |
| 맨 위 | 가동 N일차, 실행 한 줄("04:00 시작 → 완료 · 총 N분"), 수집·주제·실탐·LLM 요약 숫자, 오늘 Top 5 중 "몰랐는데 흥미로움" 개수 |
| 교차 플랫폼 Top 5 | 카드마다 주제 이름, 분야, 플랫폼, 출처 수, 처음 나타난 날, 점수(z·가속·폭), 28일 곡선, "왜 올랐나" 한 문장, 근거 3건(대표·발단·최다 논의), 실탐 요약, 읽은 범위, "몰랐는데 흥미로움" 표시 |
| 분야별 Top 3 | 분야마다 3개. "실탐"은 임계를 넘어 원문을 읽은 주제, "메타만"은 수치만 본 주제 |
| 탐색 슬롯 | 점수와 무관하게 무작위로 뽑은 5건(플랫폼·제목·수치) |
| 롤업 · 일 | 어제와 오늘을 같은 점수식으로 계산해 순위를 비교한다. 점수 순위 5위 안에 새로 든 주제, 밖으로 나간 주제, 가장 많이 오른 주제 |
| 롤업 · 주 | 지속: 최근 7일 중 점수 순위 4위 안에 든 날이 많은 주제. 신규: 처음 나타난 지 7일 안이고 오늘 8위 안인 주제. 이탈: 지난 6일 중 4위 안에 든 적이 있으나 오늘은 밖인 주제 |
| 롤업 · 월 | 한 주제를 플랫폼별로 나눠 본 28일 곡선(각 플랫폼 최대치 = 100)과, 각 플랫폼이 최대치의 50%를 처음 넘은 날로 잰 플랫폼 간 시차. 주제는 기본으로 Top 5의 1위(제안). 28일 값 표도 펼쳐 볼 수 있다 |
| 수집 상태와 오늘의 실행 | 소스별 건수·가중치·상태(정상/주의/입력 없음)와 이유, 파이프라인(수집 → 주제 → 임계 통과 → 실탐 선정 → 원문 읽기 → LLM 요약), 실행기·시간 배분·실탐 시간 예산·임계·LLM 호출 수와 토큰 |

- 처음 14일은 "기준선이 쌓이는 중 (n/14일)" 막대를 보여 주고 "지금 인기" 순으로 정렬하며, 롤업은 숨긴다.
- 카드의 "몰랐는데 흥미로움" 표시는 1번의 성공 기준을 재는 기록이다. 저장한다(8번 `feedback`).

**샘플과 달라지는 곳 (구현 때 반영)**

- 유튜브 행의 "5개 카테고리" 표기는 틀렸다(4번).
- 인스타 행은 "7/10쪽"이 아니라 하루 약 20쪽 한도이고, 수집은 하루 60개가 아니라 100개다(4번).

## 8. 데이터 구조 초안 (제안)

샘플 화면이 숫자마다 붙여 둔 저장 위치(`items`, `topics`, `topic_score` 등)에서 뽑은 초안이다. 확정이 아니라 구현 전에 같이 볼 출발점이고, 저장소는 파일 하나짜리 SQLite로 시작하는 안이 가장 단순하다.

| 테이블 | 한 행의 뜻 | 주요 열 | 보관 |
| --- | --- | --- | --- |
| `source_runs` | 소스별 하루 실행 기록 | 날짜, 소스, 수집 건수(`item_count`), 상태, 메모 | 계속 |
| `items` | 수집한 글·영상·저장소·문서 하나 | 소스, 외부 id, 제목, 출처, 링크, 올라온 시각, 처음 수집한 날 | 제목·링크·출처는 계속. 본문·자막·댓글 원문은 2~3일 |
| `item_snapshots` | 항목의 하루치 숫자 | 항목, 날짜, 조회수·별·점수·댓글·좋아요 등 | 계속 |
| `topics` | 묶인 주제 하나 | 주제 번호(T-0731 꼴), 이름, 분야, 키워드, 별칭, 처음 나타난 날(`first_seen`) | 계속 |
| `topic_items` | 주제와 항목의 연결 | 주제, 항목, 역할(대표·발단·최다 논의) | 계속 |
| `topic_daily` | 주제의 하루 어텐션 | 주제, 날짜, 어텐션(`attention`), 플랫폼별 값 | 계속. 기준선과 월 롤업의 근거 |
| `topic_score` | 주제의 하루 점수 | 주제, 날짜, z, 가속(`accel`), 폭(`breadth`), 출처 수, 점수(`score`), 순위, 임계 통과 여부 | 계속 |
| `deepreads` | 실탐 한 건 | 주제, 날짜, 종류, 읽은 범위(`scope`), 요약(`summary`), 댓글 요약, "왜 올랐나" 문장 | 계속. 7일 재탐색 금지 판단에도 씀 |
| `feedback` | 카드별 "몰랐는데 흥미로움" 표시 | 주제, 날짜, 표시 여부 | 계속. 성공 기준을 재는 기록 |
| `llm_calls` | LLM 호출 하나 | 날짜, 용도, 모델, 입력·출력 토큰 | 계속 |

- 샘플 화면에 저장 위치가 적힌 것은 `items`, `topics`, `topic_daily`, `topic_score`, `deepreads`, `source_runs`, `llm_calls`다. `item_snapshots`, `topic_items`, `feedback`은 이 문서에서 더한 제안이다.
- 원문(본문·자막·댓글)은 2~3일 뒤 지우고, 숫자 스냅샷과 점수는 기준선 28일과 월 롤업을 위해 남긴다.
- 인스타 릴스는 `items`에 넣고 계정·캡션·해시태그·소리 이름·위치 태그는 추가 열(JSON)에 둔다.

## 9. 확정된 것과 실제로 돌려 보고 정할 것

구현은 확정된 것만으로 시작할 수 있고, 열린 항목은 돌려 보면서 정한다. 기준선은 날짜가 쌓여야 생기므로 수집과 스냅샷 저장을 가장 먼저 켠다.

**확정**

- 5개 분야와 수집원. Reddit·X·LinkedIn은 자리만 둔다(3번).
- 7단계 흐름과 점수식. 상수는 시작값이다(2·5번).
- LLM은 이름·병합, 실탐 요약, "왜 올랐나" 세 곳에서만 쓴다(2번).
- 실탐은 주제당 1~3건, 7일 재탐색 금지, 하루 약 90분 예산이다(6번).
- 유튜브 댓글은 영상당 20개, 관련순이다(4번).
- 인스타는 하루 100개로 시작해 일주일 경고가 없으면 200개, 확인 페이지 약 20쪽, 멈춤 규칙을 지킨다(4번).
- 인스타 부계 샘플링은 [설계 v0](https://claude.ai/artifact/QKdGu7Qm3YZBtPHEViTbfk)의 "공개 API, 공식 경로, 사람이 직접 넣는 입력만 쓴다" 원칙의 예외다. 약관 위험을 설명했고 사용자가 골랐다.
- 원본은 2~3일, 숫자 스냅샷은 계속 보관한다(1·8번).
- 맥미니 M4 Pro 48GB에서 새벽에 자동 실행하고 오후에 확인한다(2번).

**열린 항목 (실제로 돌려 보고 정한다)**

| 항목 | 지금 값 또는 안 | 정하는 때 |
| --- | --- | --- |
| 점수 상수, 임계(5.0), 출처 최소 3곳 | 시작값 | 2주 뒤 |
| 성공 기준의 목표 개수("몰랐는데 흥미로움" n/5) | 미정 | 2주 써 본 뒤 |
| 임베딩 모델과 비슷하다고 보는 기준 | 미정 | 구현 중 시험 |
| 일별 어텐션 계산식 | 항목 속도를 플랫폼 안에서 정규화해 합산(제안) | 구현 중 |
| Top 5의 5번째(탐색 주제)를 고르는 규칙 | 미정 | 첫 주 |
| 인스타 후보 조건(계정 3곳), 가중치 0.3, 100→200 증량 | 시작값 | 1~2주 뒤 |
| 인스타 수집 도구 | Agent Reach의 인스타 기능 또는 브라우저 자동화 | 구현 중 |
| 소스 "주의" 기준 | 수집 건수가 평소보다 크게 줄 때 | 실제 수집량을 본 뒤 |
| 연예·밈 보강 소스 | 기획사 유튜브 채널 RSS(SM·HYBE·JYP·YG), 연예 뉴스 RSS, 트렌드 뉴스레터(Trend A Word) | 첫 주 돌려 본 뒤 |
| LLM을 돌릴 곳과 모델 | API(월 비용은 2번 표) 또는 맥미니 로컬 모델 | 구현 시작 때 |
| 저장소 | SQLite 한 파일(제안) | 구현 시작 때 |
| Reddit 연결 | 자리만. 접근 방식 조사는 설계 v0에 있다 | 나중에 |

**구현 전 준비물**

- 유튜브 Data API 키(무료, Google Cloud에서 발급): 사용자
- 인스타 부계에 로그인된 브라우저: 사용자가 직접 로그인하고 확인 절차도 직접 처리
- LLM API 키(API를 쓸 때): 구독과 별개로 과금
- Agent Reach 설치와 점검: 아직 안 함

**처음 순서 (제안)**

1. 소스 1~2곳(예: Hacker News, GitHub)으로 수집 → 저장 → 숫자 스냅샷까지만 만들고 매일 돌리기 시작한다.
2. 기준선이 쌓이는 동안은 "지금 인기" 모드로 피드 화면을 연결한다.
3. 나머지 소스를 하나씩 더한다.
4. 실탐과 LLM 요약을 붙인다.
5. 인스타는 마지막에 하루 100개로 켠다.
